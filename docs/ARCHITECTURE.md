# OlympRadar 2
Ежедневный Python-сбор использует sources.collect и analysis.analyze. SQLite хранит публичный каталог, историю и FTS5. Версионированный снимок публичных данных публикуется в ветке catalog-data. Worker читает компактный JSON-снимок из этой ветки и синхронизирует его с D1 для запросов. Приватные данные находятся исключительно в D1. React Mini App и API обслуживаются одним Worker на workers.dev через Static Assets. Webhook отвечает на команды, Cron проверяет локальное время подписчиков.

## Согласованность данных
Стандартный Linux runner сериализует обновления ветки catalog-data. Миграции SQLite добавляют таблицы и индексы к предыдущему снимку. История запусков фиксирует результаты источников. Ошибка отдельной площадки сохраняет ранее известные события. Дедлайн регистрации и дата окончания хранят разный смысл. Приватные избранные, настройки, подписки и журнал уведомлений находятся в D1.

## Доставка
Каждый вызов cron выбирает следующего пользователя постоянным курсором. Дата последней сводки относится к часовому поясу пользователя. Если совпадений нет, сообщение не создаётся. Перед запросом Telegram база резервирует локальную дату. Тайм-аут после резервирования может привести к пропуску одной сводки. Срочное напоминание требует явного включения и избранного события.

## Границы доверия
Worker проверяет HMAC и срок действия initData перед запросами к персональным данным. Webhook принимает POST с отдельным секретом Telegram. SQL получает параметры через binding D1. Сборщик передаёт Gemini только публичные поля, с ограничением количества запросов и локальным fallback. UI получает JSON с данными события и открывает проверенные внешние ссылки.
